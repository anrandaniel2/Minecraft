# Minecraft Vulkan overlay

This is the short Android composition path. `MinecraftVulkanOverlayPlugin` adds
an Android `SurfaceView` above Godot's content root and forwards its
`ANativeWindow` to an optional in-process VulkanMod bridge. Minecraft owns the
Vulkan swapchain; Godot remains the host activity underneath it.

The plugin does **not** patch Minecraft's RenderPearl/Blaze3D renderer and does
not pretend that the current extracted Native Image is a Fabric/VulkanMod
runtime. The client profile still has to provide a VulkanMod-compatible Fabric
runtime and export the optional callbacks:

```c
void minecraft_vulkanmod_surface_available(ANativeWindow *, int width, int height);
void minecraft_vulkanmod_surface_destroyed(void);
```

Those callbacks are looked up dynamically, so the plugin remains usable with a
launcher/client bridge that supplies them. The ABI also exports
`minecraft_vulkanmod_get_native_window`, `minecraft_vulkanmod_get_surface_width`,
and `minecraft_vulkanmod_get_surface_height` from the plugin's native library.

Enable the optional host path in `project.godot`:

```ini
[minecraft]
vulkan_overlay/enabled=true
```

Or use it directly from GDScript:

```gdscript
var overlay := MinecraftVulkanOverlay.new()
add_child(overlay)
overlay.enable_vulkanmod(true)
overlay.show_client()
print(overlay.status())
```

The export script packages the AAR generated by `android_plugin/`. The checked-
in Godot project enables this addon, but the overlay should only be shown when
a VulkanMod client profile is actually being launched; otherwise Android will
correctly report `surface_ready_client_bridge_missing`.

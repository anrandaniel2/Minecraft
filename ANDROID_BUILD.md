# Android APK Build — arm64 Only

The Android APK is built by GitHub Actions with the **real** Godot 4.4.1 Mono
Android export (Gradle build). The APK contains the actual game: engine +
.NET/Mono runtime native libraries, compiled C# game code, scenes, shaders and
the full texture set (1300+ block/GUI textures, imported as ETC2/ASTC + S3TC/BPTC).

> **No placeholders.** Earlier CI runs published a hand-made 2.4 KB "placeholder
> APK" (`godot-pck-placeholder.txt`, fake 167-byte `.so` stubs) whenever the
> export failed. Those files were removed from the repository and
> `.github/scripts/verify_android_apk.py` now rejects any APK that is not a
> verified real build before it can be uploaded or released.

## Workflow

`.github/workflows/build-android.yml` — triggers on `workflow_dispatch` or on
pushes that touch code/assets (`Scripts/`, `Scenes/`, `Assets/`, `Shaders/`,
`*.cs`, `*.csproj`, `project.godot`, `export_presets.cfg`).

Pipeline:

1. **Tooling** — .NET SDK 8 only (Godot 4.4 Mono fails with SDK 9/10 on the
   runner), Java 17, Godot 4.4.1 Mono + export templates
   (`chickensoft-games/setup-godot`), Android SDK (platform-tools, android-34,
   build-tools 34.0.0).
2. **Android build template** — `android_source.zip` from the *Mono* export
   templates is installed into `android/build/` exactly like the editor's
   *Project → Install Android Build Template* (plus `android/.build_version`).
   The job fails loudly if the template is missing — it never falls back to a stub.
3. **C# build** — `dotnet build` (Debug + ExportRelease). `Scripts/AutoGenerated`
   (decompiled reference dump with duplicate classes) is excluded via
   `Minecraft.csproj` and `.gdignore`; `extracted/` and `decompiled_sample/` are
   `.gdignore`d so they cannot leak into the exported game data.
4. **Export** — `godot --headless --export-release "Android"` with
   `gradle_build/use_gradle_build=true` (required for C# Android), arm64-v8a
   only (`export_presets.cfg`), signed with a per-run CI keystore via the
   `GODOT_ANDROID_KEYSTORE_*` environment variables.
5. **Verification gate** — `.github/scripts/verify_android_apk.py` must pass:
   - APK ≥ 8 MB and contains real `classes*.dex` (DEX magic),
   - `lib/arm64-v8a/` contains real ELF binaries: the Godot engine `.so` *and*
     the .NET/Mono runtime `.so`,
   - no `armeabi-v7a` / `x86` / `x86_64` libraries,
   - `assets/` contains the real game payload (textures, scenes, assemblies),
   - APK is signed, and no entry names contain placeholder markers.
6. **Publish** — the verified APK is uploaded as a workflow artifact and
   attached to a GitHub Release (`android-arm64-<run number>`). If verification
   fails, nothing is published.

### Why `project.godot` needs `dotnet/project/assembly_name`

Godot's C# export expects `res://<assembly_name>.sln` + `res://<assembly_name>.csproj`.
Without `dotnet/project/assembly_name` set (see the `[dotnet]` section in
`project.godot`) it falls back to a wrong default ("UnnamedProject"), then treats
the project as non-C#: no `dotnet publish`, `assembleStandardRelease` instead of
`assembleMonoRelease`, and raw `.cs` sources get packed into the APK without the
.NET runtime. The verification step rejects any APK without managed assemblies.

### Why `project.godot` must import ETC2/ASTC

`rendering/textures/vram_compression/import_etc2_astc=true` is set in
`project.godot`. Godot 4.4 refuses to export to Android (silently, with only the
ever-present *"Exporting to Android when using C#/.NET is experimental."*
message) unless ETC2/ASTC texture import is enabled — on a Linux CI runner the
auto-detection otherwise picks desktop S3TC/BPTC only. It also makes the APK
ship proper compressed textures for mobile GPUs.

## Export settings (arm64 only)

Enforced in `export_presets.cfg`:

```
architectures/armeabi-v7a=false
architectures/arm64-v8a=true
architectures/x86=false
architectures/x86_64=false
gradle_build/use_gradle_build=true
export_path="builds/Minecraft-26.3-Android-arm64.apk"
```

The verification step checks the APK really contains `lib/arm64-v8a/` only.

## Building locally

```sh
# prerequisites: .NET SDK 8, JDK 17, Android SDK (platform 34 + build-tools 34),
#                Godot 4.4.1 Mono with export templates + android_source.zip installed

dotnet restore Minecraft.csproj
dotnet build Minecraft.csproj -c ExportRelease

mkdir -p builds
godot --headless --path . --import          # import textures/scene resources
godot --headless --path . --export-release "Android" builds/Minecraft-26.3-Android-arm64.apk

python3 .github/scripts/verify_android_apk.py builds/Minecraft-26.3-Android-arm64.apk
```

Release signing locally: set `GODOT_ANDROID_KEYSTORE_RELEASE_PATH`,
`GODOT_ANDROID_KEYSTORE_RELEASE_USER` and `GODOT_ANDROID_KEYSTORE_RELEASE_PASSWORD`
(see the [Godot docs](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_android.html)).
Without them Godot signs with the debug keystore (`~/.android/debug.keystore`).

Build outputs (`builds/`, `*.apk`, `android/build/`) are git-ignored on purpose:
artifacts belong to CI releases, not to the repository.
